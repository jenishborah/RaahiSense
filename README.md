# RaahiSense

### A Temporally Structured Historical Vehicle-Intelligence Pipeline for Evidence-Grounded Vehicle Behaviour Analysis

RaahiSense is an MTech Data Science research project focused on building a **temporally structured vehicle-intelligence pipeline** for retrieving and explaining relevant historical vehicle-behaviour evidence from heterogeneous, timestamped data.

The project investigates whether **temporal structure, contextual information, and evidence ranking** can improve the retrieval of relevant vehicle-behaviour evidence and the grounding of explanations generated by a resource-constrained local language model.

---

## Research Objective

> To evaluate whether temporal and contextual evidence retrieval improves the retrieval of relevant vehicle-behaviour evidence and the grounding of resource-constrained language-model explanations.

RaahiSense focuses on **historical vehicle intelligence**, rather than autonomous vehicle control.

The system processes heterogeneous timestamped data, detects events and contexts, establishes temporal relationships, retrieves relevant historical evidence, and prepares evidence packages for a local SLM.

---

## Research Questions

1. How does temporal structure affect retrieval of relevant vehicle-behaviour evidence?
2. Can temporal and contextual ranking improve evidence retrieval compared with basic retrieval methods?
3. Does structured evidence improve the grounding and traceability of SLM-generated explanations?
4. Which historical vehicle-intelligence query classes benefit most from structured temporal retrieval?
5. What are the performance and resource trade-offs when deploying the pipeline on constrained edge hardware?

## Database

RaahiSense currently uses **SQLite** for the initial historical storage and retrieval layer.

The database schema is defined in `database/schema.sql`.

The schema uses:

- UUIDv7 identifiers stored as `TEXT`
- Unix epoch milliseconds stored as `INTEGER`
- JSON stored as `TEXT`
- SQLite foreign-key constraints
- Indexed temporal queries
- Explicit data-origin tracking
- Explicit data-quality information
- Ground-truth and detected-event separation

### Data Origins

```text
synthetic
simulation
replay
physical
```

Synthetic data is explicitly distinguished from real-world measurements.

## Synthetic Scenario Generator

Controlled synthetic scenarios are generated using `generator/synthetic_generator.py`.

The generator is intended to produce controlled datasets containing:

- Vehicle signals
- Road-user signals
- Environmental conditions
- Vehicle behaviour
- Sensor noise
- Missing data
- Timestamp jitter
- Source delays
- Conflicting evidence
- Hidden ground truth

Synthetic data is primarily used for **controlled experimentation and evaluation**, particularly where precise ground truth is difficult to obtain from real-world data.

---

## Event Detection

Events are intended to be detected from observations rather than being treated simply as manually inserted analytical labels.

Examples include:

```text
SHARP_BRAKING
PEDESTRIAN_DETECTED
VEHICLE_DETECTED
COLLISION_WARNING
LANE_DEPARTURE_WARNING
EMERGENCY_BRAKING
```

Detected events contain information such as event type, timestamps, severity, confidence, detection method, detection version, trigger observation, and data origin.

---

## Temporal Relationships

Supported relationships include:

```text
PRECEDES
FOLLOWS
OVERLAPS
CO_OCCURS
WITHIN_WINDOW
ASSOCIATED_WITH
```

The system intentionally does **not** use a generic `CAUSES` relationship. Temporal proximity or association must not automatically be interpreted as causation.

The database therefore includes `causal_claim_allowed` as an explicit guard against unsupported causal explanations.

## Example Historical Query

> Why did the vehicle brake sharply at 10:42 AM?

The system should retrieve evidence such as:

```text
Pedestrian Detection
        |
        v
Pedestrian Distance
        |
        v
Vehicle Speed
        |
        v
Rapid Deceleration
        |
        v
Brake Activation
        |
        v
Post-event Vehicle Speed
```

The resulting explanation must describe the observed temporal sequence without making unsupported causal claims.

## Evaluation

RaahiSense evaluates multiple retrieval strategies:

```text
Baseline 1: Raw / Keyword Retrieval

        VS.

Baseline 2: Structured Event Retrieval

        VS.

Proposed: Temporal + Contextual Evidence Retrieval
```

Evaluation areas include:

- Event detection: Precision, Recall, F1-score
- Retrieval: relevant evidence, temporal relevance, context relevance, ranking quality
- Grounding: evidence coverage, traceability, unsupported claims, grounded explanation quality
- Edge performance: latency, memory, storage, inference cost

## Ground Truth Policy

Ground truth is kept separate from the evidence available to the retrieval system during evaluation. This prevents the retrieval system from directly accessing the answer it is expected to retrieve.

## Local SLM

After the retrieval pipeline is evaluated, a resource-constrained local language model will be integrated.

The SLM is not intended to independently discover the evidence. Instead:

```text
User Query
    |
    v
Historical Retrieval
    |
    v
Temporal / Contextual Ranking
    |
    v
Evidence Package
    |
    v
Local SLM
    |
    v
Grounded Explanation
```

---

## Edge Deployment

The final system is intended to be evaluated on resource-constrained hardware, with a Raspberry Pi-class device considered as a target platform.

The edge evaluation will investigate the trade-off between accuracy, retrieval quality, latency, memory, storage, model size, and computational cost.

RaahiSense does not attempt to build a complete autonomous-driving system.

## Installation

```bash

cd RaahiSense
```

Create a virtual environment.

### Windows

```powershell
python -m venv .venv
.venv\\Scripts\\Activate.ps1
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Initialize the Database

The SQLite database is generated from `database/schema.sql`.

Example:

```powershell
python -c "import sqlite3; from pathlib import Path; db=Path('data/database/raahisense.db'); db.parent.mkdir(parents=True, exist_ok=True); con=sqlite3.connect(db); con.executescript(Path('database/schema.sql').read_text()); con.close(); print('RaahiSense database created successfully')"
```

The database file is intentionally excluded from Git. The schema is version-controlled so that the database can be reproduced locally.
